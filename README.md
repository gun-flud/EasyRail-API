# EasyRail API — Паспорт продукту

> **Високонадійний REST API для інтелектуального пошуку маршрутів, динамічного розкладу та інтервального бронювання залізничних квитків без овербукінгу.**

---

## 1. Про проєкт (Mission & Overview)

**EasyRail** — це спеціалізований бекенд-сервіс для пасажирських залізничних перевезень. 

Залізнична логістика має лінійну топологію зі змінним пасажиропотоком. Замість блокування місця на весь маршрут, EasyRail реалізує алгоритм **інтервального бронювання (Interval Segment Booking)**: одне фізичне крісло можна продавати різним пасажирам на послідовних неперетинних відрізках (наприклад, *Київ → Вінниця* та *Вінниця → Львів*). Це максимізує місткість поїздів і виключає подвійні продажі.

**Інженерна мета:** Практичне дослідження та побудова відмовостійкої, конкурентної системи з транзакційною ізоляцією, розрахунком колізій на відрізках у реальному часі та незмінними фінансовими зліпками (Snapshot Pattern).

---

## 2. Ключові можливості та бізнес-правила

### Пошук та розклад
* Пошук поїздів за станціями та датою з перевіркою коректного напрямку: $\text{stop\_order}_{\text{from}} < \text{stop\_order}_{\text{to}}$.
* Відображення схеми вагона із зайнятими та вільними полицями (нижні/верхні/бічні).
* Автоматичне приховування повністю заповнених поїздів (`SOLD OUT`).

### Бронювання та купівля
* **10-хвилинний резерв (Hold):** Тимчасове блокування вибраних перегонів. Автоматичний воркер звільняє неоплачені місця (`EXPIRED`) без блокування бази даних завдяки `SKIP LOCKED`.
* **Правило ліміту:** Не більше **1 активного холду** на одного користувача одночасно.
* **Збережені попутники:** Оформлення квитків собі або іншим пасажирам з автозбереженням їхніх профілів для купівлі в один клік у майбутньому.
* **Snapshot Pattern:** Після оплати (`PAID`) у квиток назавжди записується незмінний зліпок даних (ПІБ, станції, час, ціна), захищений від майбутніх змін розкладу.

### Сповіщення
* Нагадування пасажирам за **60, 30 та 15 хвилин** до відправлення рейсу.
* Миттєві тригерні повідомлення про скасування, затримку поїзда або повернення квитка.

### Повернення коштів (Refunds)
* **Правило 2-х годин:** Повернення можливе лише якщо до відправлення залишається $> 2\text{ hours}$. Якщо $\le 2\text{ hours}$ — операція блокується.
* **Тарифна сітка штрафів:** 
  * $> 24\text{ год}$: повернення $90\%$ (штраф $10\%$);
  * $2–24\text{ год}$: повернення $70\%$ (штраф $30\%$).
* **Soft Delete:** Фізичний запис не видаляється, а маркується `CANCELLED`, звільняючи сегменти місця у відкритий продаж.

## 4. Технологічний стек

* **Runtime & Мова:** Node.js 22 LTS, TypeScript 5.x (`NodeNext`, `verbatimModuleSyntax`, `noUncheckedIndexedAccess`).
* **Веб-сервер:** Fastify v5 (висока пропускна здатність, модульна архітектура).
* **Контракти та валідація:** Zod + `fastify-type-provider-zod` (Single Source of Truth).
* **База даних:** PostgreSQL 16 (Alpine) + Drizzle ORM (транзакції, `SELECT ... FOR UPDATE`, часткові індекси).
* **Тестування:** Vitest (інтеграційне тестування через `app.inject()` без підняття відкритих портів).
* **Документація:** OpenAPI 3.0 / Swagger UI (`/docs`).
* **DevOps:** Docker Multi-Stage Build ($\approx 150\text{ MB}$, непривілейований `USER node`), Docker Compose, pnpm v9.

## 5. Швидкий запуск

### Запуск через Docker Compose (Рекомендовано)

```bash
# 1. Клонувати репозиторій
git clone https://github.com/your-username/EasyRail-API.git
cd EasyRail-API

# 2. Запустити базу даних та API
docker compose up --build -d
```

* **API:** `http://localhost:3000`
* **Swagger UI:** `http://localhost:3000/docs`
* **PostgreSQL:** `localhost:5432` (`easyrail_user` / `easyrail_pass` / `easyrail_db`)

### Локальна розробка

```bash
cd backend
pnpm install
cp .env.example .env
pnpm dev
```
