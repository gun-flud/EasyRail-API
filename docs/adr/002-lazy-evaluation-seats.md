# ADR 001: Відмова від фізичних місць на користь Lazy Evaluation

**Статус:** Затверджено  
**Дата:** Жовтень 2026  
**Контекст:**  
Система має управляти доступністю місць у вагонах. Маршрут може мати десятки зупинок, а поїзд — сотні місць. Класичний підхід вимагає генерації стану вільно/зайнято.

**Розглянуті альтернативи:**  
1. **Повна генерація (Pre-generated Seats):** Створити таблицю `Seats` та генерувати мільйони рядків для кожного порожнього місця, кожного вагона, на кожному перегоні для всіх рейсів на пів року вперед.
2. **Lazy Evaluation (Віртуальні місця):** Зберігати геометрію та нумерацію місць у статичній таблиці-довіднику (`Seat_Templates`). Запис у базі створюється виключно в момент, коли місце купується (сутність `Ticket_segment`).

**Прийняте рішення:**  
Обрано підхід **Lazy Evaluation** (віртуальні місця). Для управління зайнятістю місць ми використовуємо математичну логіку перетину інтервалів зупинок: запис у `Ticket_segment` із вказаними `from_stop_order` та `to_stop_order` виступає блокуванням цього відрізка для інших.

**Наслідки:**  
* **Позитивні:** Запобігання експоненційному роздуванню бази даних мільйонами порожніх рядків. Дозволяє гнучко перепродавати одне місце на різних ділянках шляху без овербукінгу, використовуючи лише логіку перетину `MAX(A, C) < MIN(B, D)`.
* **Негативні:** Пошук вільних місць потребує складніших SQL-запитів до бази даних, щоб відфільтрувати наявні `Ticket_segment` і вирахувати "пустоти".
