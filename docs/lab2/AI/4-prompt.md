# Промпт 4. Уточнення кабінетів і діаграм

## Мета

Доопрацюй діаграми EasyRail, щоб чітко відобразити відмову від бронювання, розмежування кабінетів користувача й адміністратора та зв'язки між акторами й Use Cases. Також створи еквівалентну діаграму PlantUML для зручнішого перегляду.

## Що потрібно змінити

### 1. Відмова від бронювання в кабінеті користувача

- Покажи, що користувач може відмовитися від активного холда у своєму особистому кабінеті.
- Після відмови система знімає активний статус бронювання, переводить квиток у `EXPIRED` і звільняє місце для інших пасажирів.
- Збережи цю поведінку послідовною в діаграмі та пов'язаних вимогах/Use Cases.

### 2. Розмежування кабінетів

- Кабінет користувача призначений лише для пасажира: перегляд власних поїздок і керування власними квитками.
- Адміністратор не повинен бути показаний як користувач цього кабінету.
- Перегляд статистики навантаження потягів розмісти в окремому кабінеті адміністратора. Якщо в наявних матеріалах є кращий узгоджений варіант, коротко обґрунтуй його та застосуй послідовно.

### 3. Перевірка зв'язків на діаграмі

- Переглянь зв'язки акторів і Use Cases: залиш лише ті, що логічно відповідають описаній поведінці.
- Зроби структуру зрозумілою без необхідності здогадуватися про значення зв'язків.
- Збережи відповідність між вимогами та Use Cases: кожна вимога має бути підкріплена відповідним Use Case, а зв'язки мають залишатися доступними для подальшої матриці трасування.
- Не додавай непідтверджених вимог або функцій.

### 4. Створення діаграми PlantUML

- Додай окремий файл PlantUML з тією самою інформацією та змістом, що й наявна діаграма `model.mmd`.
- Не змінюй обсяг функціональності під час перенесення діаграми в інший формат.
- Перевір, що актори, Use Cases, зв'язки та ключові переходи узгоджені між обома діаграмами.

## Вимоги до результату

- Документи мають бути чіткими, зрозумілими та лаконічними.
- Діаграми мають бути охайними й легко читатися.
- Зміни в діаграмах, вимогах і Use Cases не повинні суперечити одна одній.
- Наприкінці коротко переліч змінені файли та підтверди, що відповідність вимог Use Cases збережено.
