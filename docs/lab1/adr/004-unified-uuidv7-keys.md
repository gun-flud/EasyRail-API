# ADR 004: Використання UUIDv7 як єдиного стандарту ідентифікаторів

**Статус:** Затверджено  
**Дата:** Жовтень 2026  
**Контекст:**  
При проєктуванні концептуальної моделі EasyRail виникла потреба обрати єдиний стандарт типів даних для первинних (PK) та зовнішніх (FK) ключів. Система передбачає публічні ендпоінти для перевірки статусу квитка та профілів користувачів.

**Розглянуті альтернативи:**  
1. **INT (Auto-increment/Serial):** Висока швидкість, але небезпечно для публічних API. Дозволяє конкурентам або зловмисникам передбачити кількість сутностей у базі та виконати атаку типу IDOR (перебір ID користувачів чи квитків).
2. **UUIDv4:** Повністю випадкові та безпечні. Однак через рандомність вони викликають сильну фрагментацію індексів B-Tree в базі даних, що суттєво знижує продуктивність при великих обсягах даних (INSERT penalty).
3. **UUIDv7:** Новий концептуальний стандарт, який поєднує безпеку UUID із міткою часу (timestamp) у перших бітах.

**Прийняте рішення:**  
Усі первинні та зовнішні ключі в системі будуть використовувати концептуальний тип `uuid` з архітектурною імплементацією **UUIDv7**.

**Наслідки:**  
* **Позитивні:** Ми гарантуємо криптографічну безпеку ключів (неможливо вгадати номер чужого квитка). База даних зберігає високу продуктивність, оскільки ключі генеруються послідовно в часі (Time-ordered), що забезпечує компактність індексів.
* **Негативні:** Ключі займають більше місця (16 байт) порівняно зі звичайним INT (4 байти), проте це є виправданим компромісом задля безпеки.
