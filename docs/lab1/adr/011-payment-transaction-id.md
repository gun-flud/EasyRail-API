# ADR 011: Зберігання ідентифікатора платежу в `ticket_segment`

**Статус:** Затверджено  
**Дата:** Жовтень 2026

**Контекст:**  
Оплата квитка виконується зовнішнім платіжним процесом. Після підтвердження оплати система має зберегти отриманий ідентифікатор транзакції, щоб надалі зіставляти квиток із платежем, зокрема під час повернення коштів. У початковій моделі `ticket_segment` такого атрибута не було.

**Розглянуті альтернативи:**
1. **Не зберігати ідентифікатор транзакції:** квиток не матиме прямого посилання на відповідний платіж, що ускладнить його пошук та обробку повернення.
2. **Зберігати ідентифікатор у `ticket_segment`:** пов'язати квиток із транзакцією безпосередньо в записі, який відображає його життєвий цикл.

**Прийняте рішення:**  
Додати до `ticket_segment` атрибут `payment_transaction_id` типу `string`. У ньому зберігається ідентифікатор, отриманий від зовнішнього платіжного процесу, для зв'язку квитка з оплатою та її подальшої ідентифікації під час повернення коштів.

**Наслідки:**
- **Позитивні:**
  - Ідентифікатор платежу доступний разом із даними квитка.
  - Платіж можна зіставити з квитком під час обробки повернення.
- **Негативні та обмеження:**
  - Це рішення передбачає зберігання ідентифікатора транзакції на рівні квитка; окремий облік кількох спроб оплати або кількох транзакцій для одного квитка цією моделлю не описується.
